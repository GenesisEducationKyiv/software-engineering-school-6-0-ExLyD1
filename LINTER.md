# Налаштування лінтера

## Інструмент

ESLint з інтеграцією TypeScript та Prettier.

## Чому ESLint

Обрав ESLint через популярність — це найвідоміший інструмент для Node.js/TypeScript проєктів.

Після дослідження альтернатив маю чесний висновок:

## Порівняння альтернатив

|                      | ESLint         | Biome         | oxlint         |
| -------------------- | -------------- | ------------- | -------------- |
| Швидкість            | Повільна       | 10-20x швидше | 50-100x швидше |
| TypeScript підтримка | Найкраща       | Хороша        | Базова         |
| Екосистема плагінів  | Величезна      | Мала          | Майже немає    |
| Форматування         | Через Prettier | Вбудоване     | Немає          |
| Зрілість             | 10+ років      | ~2 роки       | ~1 рік         |

## Висновки

**ESLint** — найглибша підтримка TypeScript через `@typescript-eslint`, type-aware правила, величезна екосистема. Головний мінус — швидкість.

**Biome** — на власних проєктах планую використовувати саме його. Вбудоване форматування замість окремого Prettier, набагато швидший, тримає баланс між швидкістю oxlint та підтримкою ESLint. Для стартапів — виглядає як оптимальний вибір.

**oxlint** — найшвидший, але скоріше доповнення до ESLint ніж заміна. Використовують разом: oxlint робить швидкий перший прохід, ESLint робить глибокий аналіз.

Щодо повільності ESLint на великих проєктах — з enterprise масштабом не працював, тому не можу впевнено сказати наскільки ті секунди лінтингу критичні на практиці.

## Плагіни

- `@typescript-eslint` — type-aware правила для TypeScript
- `eslint-plugin-prettier` — запускає Prettier як ESLint правило
- `eslint-config-prettier` — вимикає ESLint правила що конфліктують з Prettier

## Скрипти

```bash
npm run lint       # перевірка помилок
npm run lint:fix   # виправлення помилок
```
